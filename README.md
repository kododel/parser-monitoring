# Мониторинг цен: парсер, история, уведомления

Инструмент собирает товары и цены с сайта, ведёт историю замеров, присылает
в Telegram уведомление об изменении цены и выгружает всё в Excel с графиком
динамики.

Заказчику это нужно, когда он вручную проверяет цены конкурентов: селлеры
на маркетплейсах, магазины, поставщики, отделы закупок.

---

## Что умеет

- **Сбор постранично** — обходит страницы каталога, пока есть ссылка «следующая».
- **История цен** — каждый замер пишется в базу, а не только изменения:
  без истории не построить график и не ответить на вопрос «а сколько это
  стоило в марте».
- **Определение изменений** — сравнивает с предыдущим замером, считает
  разницу в валюте и процентах, отдельно отмечает подешевевшее.
- **Уведомления в Telegram** — о новых товарах и изменениях цен; молчит,
  если ничего не произошло.
- **Excel с графиком** — пять листов: товары, изменения, история, динамика
  с линейным графиком и сводка.
- **Вежливый обход** — пауза между запросами, повторы с нарастающей задержкой,
  проверка `robots.txt`, честный User-Agent с контактом.
- **Корректные цены** — понимает `£51.77`, `$1,234.56`, `1 234,56 ₽`, `12,50 €`
  и не путает тысячный разделитель с десятичным.

## Быстрый старт

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env             # вписать токен бота, если нужны уведомления
```

Демонстрационный сайт `books.toscrape.com` — учебный полигон, специально
созданный для отработки парсинга. Токен Telegram для него не нужен.

```bash
python -m parser.cli sites                    # что настроено
python -m parser.cli parse --pages 2          # собрать две страницы
python -m parser.cli stats                    # сводка по базе
python -m parser.cli report                   # выгрузить Excel
python -m parser.cli watch                    # собрать и уведомить в Telegram
```

Отдельные команды удобно повесить в cron:

```cron
# каждый день в 9:00 собираем цены и уведомляем об изменениях
0 9 * * * cd /path/to/parser-monitoring && .venv/bin/python -m parser.cli watch >> logs/monitor.log 2>&1
```

## Как подключить свой сайт

Код трогать не нужно — достаточно добавить запись в `config/sites.json`:

```json
{
  "my_shop": {
    "title": "Магазин конкурента",
    "base_url": "https://example.com/",
    "start_url": "https://example.com/catalog/page-1/",
    "max_pages": 20,
    "request_delay": 2.0,
    "respect_robots": true,
    "in_stock_text": "в наличии",
    "selectors": {
      "item": "div.product-card",
      "link": "a.product-name",
      "title_attr": "title",
      "price": "span.price",
      "availability": "span.stock",
      "rating": "div.rating",
      "next_page": "a.next-page"
    }
  }
}
```

Обязательны только `item`, `link` и `price` — остальное по желанию.
Селекторы берутся из DevTools браузера: правой кнопкой по элементу →
«Просмотреть код» → «Copy selector».

Добавить сайт в работу: `python -m parser.cli parse --site my_shop`.

## Как устроено и почему так

**Селекторы вынесены в JSON.** Самая частая задача в таких проектах —
«сайт поменял вёрстку» или «добавь ещё один магазин». Если селекторы лежат
в коде, каждая правка — это правка программы. В JSON — это правка настройки,
которую заказчик может сделать сам.

**Обход вежливый, а не быстрый.** Пауза между запросами, повторы с задержкой
на 429 и 5xx, проверка `robots.txt`, User-Agent с контактом. Парсер, который
бьёт по сайту в 20 потоков, приносит заказчику не данные, а блокировку по IP.
Если сайт запрещает обход в robots.txt — инструмент откажется работать,
и об этом честно написано в логе.

**История пишется всегда.** Даже когда цена не изменилась. Иначе не построить
график и не понять, как цена вела себя раньше. Изменения дополнительно
фиксируются в отдельной таблице — по ним строится отчёт.

**Есть порог чувствительности.** Разница меньше копейки изменением не считается:
сайты иногда отдают `199.9999999` вместо `200.0`, и без порога каждая
такая мелочь превращалась бы в уведомление.

**Смена валюты не считается изменением цены.** Сравнивать рубли с долларами
бессмысленно, поэтому такой случай логируется как предупреждение, а не
превращается в ложное «подешевело на 80%».

**Отсутствие блока «наличие» — это не «нет в наличии».** Если селектор задан,
а элемента на карточке нет, считается, что товар доступен. Пометить «нет
в наличии» весь каталог из-за изменившейся вёрстки хуже, чем показать
лишний товар: заказчик увидит ложную тревогу и перестанет доверять мониторингу.

**Уведомления молчат, когда нечего сказать.** Бот, который пишет «цены
не изменились» каждый час, быстро раздражает — и его отключают вместе
с полезными уведомлениями. Флаг `--always` заставляет писать всегда.

**Уведомления — через голый Bot API.** Для отправки сообщения фреймворк
не нужен, хватит `requests.post`. Меньше зависимостей — меньше поводов
для поломки при обновлении.

## Проверка

```bash
python tests/smoke_test.py
```

106 проверок, **интернет не нужен**: страница лежит в `tests/fixtures/`.
Проверяются разбор цен (включая ловушки с разделителями), разбор карточек
с битыми и неполными данными, соблюдение `robots.txt`, определение изменений
цены, порог чувствительности, смена валюты, сборка Excel с графиком
и сквозной прогон по двум страницам.

## Что можно доработать

- **Telegram-бот с командами** — посмотреть цены и историю по товару прямо в чате.
- **Отслеживание наличия** — уведомление, когда товар появился или пропал.
- **Сравнение с конкурентами** — сводная таблица «наш товар против пяти чужих».
- **Обход через прокси** — если сайт ограничивает по IP.
- **Расписание из коробки** — встроенный планировщик вместо cron.
- **Выгрузка в Google Sheets** — вместо файла, который надо скачивать.
- **Веб-панель** — графики в браузере, если Excel уже неудобен.
- **Контроль вёрстки** — уведомление, если селекторы перестали находить товары
  (сейчас такое видно только в логах).
